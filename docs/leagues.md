# FriendsLeague

The authenticated League tab supports multiple private leagues, creation with an immutable IANA timezone, member lists, admin rename/invitation generation, and explicit authenticated invitation confirmation. Generating an invitation opens a share card. Tap the link to copy it and see a confirmation, or use Share. Invite links remain reusable for 48 hours; recipients may open them directly or paste the link/token into Join a league. After sign-in, an invitation link opens a centered card with the league logo, title, description, member count and creation date. Join confirms membership, and the top-right close icon dismisses the card. Existing members see a membership confirmation with an option to open the league. Join a league opens a dialog for pasting an invitation, followed by the same preview card. Creation supports an optional picture and description plus a searchable IANA timezone selector. Admins can open Edit from League information. Membership starts at the exact acceptance instant and grants no retroactive credit.

The League tab follows the shared dark screen header, spacing and typography conventions. Leagues use rounded surface cards showing the league picture/name, your current-week rank and total member count; creation and joining use shared text fields and distinct primary, positive and neutral actions. Standings open on the current league week. Use the round dropdown above the standings to pick **All rounds**, the **Current round**, or an earlier round by date. Rankings and Points breakdown share the same selection. All rounds omits the round ID to fetch the combined league history. A round without credited workouts shows an empty breakdown. The breakdown lists credited workouts, points and your own calculation inputs. Both views load more rows as you scroll. Ranked rows load in pages as you scroll and mark your row as **You**. Open a member from About, Rankings, or Points breakdown to see their credited daily scores across rounds, including exact points, round dates and the completed workout reference. Calculation inputs display up to three decimal places. Switching league views reuses fresh score data and refreshes stale data when it is needed. Only the score owner sees their calculation inputs. The selected league’s picture and name replace the generic screen heading; pressing its name opens League information, with **About** and **League rules** tabs. About contains the league description, membership and admin invitation action. League rules contains fixed-rule summaries and hints. Admins can use **Edit** in the header and promote or demote eligible members in About. Protected roles, including the creator and the viewing admin’s own role, show a disabled control to admins. League information, standings and member score history fill the screen without main navigation. Back returns through the league screens to the league list. Round results use a bounded, centered dialog.

List ranks use the same league-local current week and shared-rank ties as current standings, including zero-score members. Member counts include all current members. Older leagues without a calendar or exact membership timestamp show **Weekly rank unavailable**. Opening the League tab again refreshes the summaries; the list does not fetch every league’s complete standings.

Admins can stage a picture selection or removal while editing. Save applies the name, description and picture together. Failed saves retain the draft for retry. JPEG, PNG and WebP files up to 5 MiB are normalized by the backend. Existing leagues retain a trophy fallback. List/header images refresh after saving and persist across reloads. Members can read pictures through authenticated endpoints; outsiders cannot.

Member lists, standings, daily contributions and result standings show each person beside their current profile image, with an initial fallback. Uploaded profile images use a league-scoped, member-authorized image endpoint rather than exposing another account’s private profile route. Existing HTTPS profile images are supported. Historical result names/scores remain saved while profile pictures refresh. Rules are fixed; this view does not introduce custom scoring or calendar editing.

Selected leagues show the approved fixed rules, current/past round standings, general standings and daily contributions. Integer scores remain exact decimal strings. Only your contributions expose source workout and calculation inputs; another member cannot inspect your body weight or private workout details. The fixed score is confirmed gym volume × elapsed hours / snapshotted profile weight, rounded to an integer with halves up. Each local start day credits only the highest scoring session; equal scores use earliest completion then source ID.

Weeks run Monday 00:00 inclusive through the next Monday 00:00 exclusive in the league timezone, including daylight-saving changes. The first week is partial. General totals retain all rounds including the current round. Historical persistence-only leagues without an agreed timezone/exact membership timestamp require explicit migration; the app shows a calendar error rather than inventing history.

A selected league fetches persisted pending round outcomes oldest first. The dialog identifies every tied lowest-score member (or no losing outcome with fewer than two participants) and shows saved standings. Only pressing **Got it** acknowledges the displayed result for your membership. Failed acknowledgement retains the dialog for retry. Acknowledged results do not automatically return after reopening; crashes or simultaneous devices can display an unacknowledged result again. Closure assigns no penalty and publishes no post.

Penalty pools/roulette, social sharing, editable calendars, dynamic formulas/challenges, leaving/expulsion/transfer/deletion are outside this increment.

## Verification

Focused Jest tests live under `src/features/leagues/test`. The browser flow also covers league-picture upload, failed replacement/retry, removal, reload persistence, member image retrieval and admin/member/outsider permissions. Browser acceptance uses `e2e/web/friends-league.spec.ts` against a run-owned `friends_league_*_test` database, three private synthetic identities and the actual Basic login/API. Set the existing E2E variables plus `KINETIX_E2E_EMAIL_OUTSIDER`, `KINETIX_E2E_PASSWORD_OUTSIDER`, `KINETIX_BACKEND_ROOT`, `APP_ENV=test` and `DATABASE_URL`. The fixture only prepares named test leagues and a synthetic exercise. It ages test-owned membership/creation times to exercise scoring and an expired all-zero round without waiting a week; actual sessions, closure and acknowledgements use the real API.

Run `pnpm exec playwright test --config e2e/web/playwright.config.ts friends-league.spec.ts`. Keep credentials, traces and generated artifacts private. Android/iOS evidence remains separate; the browser suite does not prove native behavior or production Clerk providers.

Android flow files are `.maestro/friends-league.yaml`, `friends-league-join.yaml` and `friends-league-result.yaml`. They require an isolated build/emulator, private `MAESTRO_KINETIX_E2E_EMAIL` / `MAESTRO_KINETIX_E2E_PASSWORD`, `MAESTRO_LEAGUE_NAME` and a private invitation for the join flow. Result preparation must use only a named run-owned test league. On 17 November 2026 the APK compiled, installed and launched on Android API 34, but the app failed before login with `RNSModule` / null `FabricUIManager`; these native flows are **not passing acceptance evidence**. The browser journey passes; Android acceptance requires a working base native runtime. No iOS acceptance was performed.
